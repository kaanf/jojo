# Open decisions requiring user approval

Status: all decisions below are **proposed**, none approved by this audit. Stage 1 authorizes research only. Implementation, remote repository creation and deployment remain stopped. Details: [architecture](PROPOSED_ARCHITECTURE.md), [source audit](../research/REPOSITORY_AUDIT.md), [extraction matrix](../research/COMPONENT_EXTRACTION_MATRIX.md).

## Decisions to settle before a prototype

| D04 | Provider boundary and order | User-installed, unmodified official CLIs with existing native subscription login. Implement Codex bounded jobs first, then Claude parity; no factory token storage or API fallback | Establish keyless scope and policy re-check before integration. ## What does not need a strategic approval now

After implementation is explicitly authorized, routine choices such as internal function naming, a small module split or parser fixture filenames can use engineering judgment. Exact Rust crate versions should be selected and checked then, rather than falsely treated as audited in Stage 1. Existing restrictions remain: no API keys, no paid calls without new explicit authorization, no touching `agentic-factory`, and no remote repositories at this stage.

## Suggested first approval bundle

Approve or amend D01, D03–D09 and a bounded D02 policy: focused Rust helper + SQLite, adapted feature artifacts, user-owned official CLI auth, conservative approvals, scoped local execution, safe crash interruption and one sample feature. D10 remains read-only; D11–D20 can be resolved as their stages approach. Approving the architecture alone is not permission to create remote repositories or deploy.

Once the user chooses, record each accepted decision as an ADR with alternatives, rationale, scope and date; retain rejections and revisions. No ADR is marked accepted by the audit itself.
