## Decisions in force

- Strategy: Reuse > Port > Adapt > Build. Keep the Rust core and the SwiftUI app. Prefer native CLI subscriptions over API keys.
- Code sources: Vigla (Apache-2.0) and weft (owner's permission reported by the human on 2026-11-15; no written record in the project). Prompts and test cases from spec-kit, factory, commandcenter, fabro.
- Approvals: four kinds, no approve-all (spec, plan, push, PR). Push and PR are built (M5): requested on Source Control, authorized each on its own in the Approval Inbox; only the branch of a finished plan run is pushed, to `origin`, under its own name, never forced; the pull request is a draft against the remote's default branch with a title and body the core builds.
- Repair: automatic, at most two tries, then a human hold. External actions are never retried automatically. Built in M4: the limit (0 to 2) and the cross-provider reviewer are set per project, from its newest revision; a review approves nothing.
- Executables: discovered automatically through the login shell's PATH and checked again before each run; version and digest recorded per run; a change is a warning, not a refusal (D3). Pinning with all three options restores the refusal.
- Feature Chat and the project record come before the demo.
- Escaped agent child processes are signalled after a freeze-and-check of PID and start time (E1). Inspection stays on `/bin/ps`; the system-call version is deferred to Phase 4 (E2).

## Known gaps
