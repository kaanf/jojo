## Implementation and invariant preservation

`jojo-domain::stream` implements byte-oriented NDJSON framing with exact raw ranges, persistent fragmented UTF-8/record state, max+1 overflow detection and bounded discard-to-newline resynchronization. Synthetic, explicitly fingerprinted Claude/Codex profiles normalize session/turn, text, tool, usage, error and explicit terminal evidence into existing P1-08 payloads. Missing/changed session identity, malformed UTF-8/JSON, excessive nesting, oversized/unterminated records and duplicate terminal records latch protocol failure. Explicit Codex error/interrupted/unknown status is never promoted to success. Neither EOF nor exit-zero manufactures terminal success; OS process observations are separate from provider evidence.

`jojo-storage::launch` journals issuance through the existing scheduler outbox before any spawn. It checks current owning epoch, generation 1 (one invocation per attempt), scheduler/plan/step/feature/provider/repository/worktree bindings, exact frozen OS request, source-vector/base/common-dir references, prompt digest and current approval decision references. Sixteen forged/stale variants are rejected before issuance or spool creation. Existing reservation/approval/admission checks remain authoritative. Each continuation/retry requires a new attempt; an uncertain spawn remains issued-unknown and is never replayed. The DB writer never waits inside a transaction for spawn or process I/O.

`jojo-storage::process` uses `std::process`, explicit executable/argv/cwd, cleared environment plus allowlisted values, fresh process group, piped stdio and a bounded prompt writer. Provider children inherit neither DB nor control/lock descriptors. Each output pipe has its own bounded reader and exclusive 0600 spool inside a 0700 generation directory. File creation directories are synced before spawn; raw bytes are written and synced before event byte ranges/checkpoints are committed. Memory limits include 64 KiB read chunks, eight channel messages, at most 1 MiB per protocol frame, four MiB of inspector stdout and 1,024 known descendants. Each raw stream has an explicit cap (maximum 256 MiB); after cap/failure readers discard/drain and expose loss. Final checkpoints are also committed for eventless stdout and small stderr below the normal checkpoint threshold; normalized events are not required for raw evidence. Spool or DB failure closes admission and triggers stop while retaining the last durable coverage.

PID safety uses ownership rather than a snapshot-to-kill guess. The direct group leader is deliberately kept **unreaped** while any observed group member remains live; its numeric PID/PGID therefore cannot be recycled during authorized group signals. Zombie-root observation and actual wait status are recorded separately; a confirmed tree-absent report always includes actual wait status. After reaping, group signals are refused. Bare snapshot-matched PIDs, including known escaped descendants, are never signalled. Changed start identity is refused; missing identity/inspection failure is UNKNOWN. The wrong-PID test also asserts that an exact matching bare PID is refused and that no group signal is sent after reaping. The retained-zombie test proves group identity stays pinned across root death and child termination.

The control path is independent of bounded output delivery. Capability policy chooses INT only when supported, followed by TERM/KILL with injected budgets (accepted defaults 10/20/5 seconds). The injected execution deadline also requests stop. Stop intent, signal delivery, observed root death, stream closure and tree absence are different facts. Whole-drain deadlines and bounded system-tool inspection prevent a pipe holder or denied inspection from wedging supervision. Unknown tree/stream state ends `STOP_UNCONFIRMED`; claims remain held. Drop and thread-start failure paths make best-effort owned-process cleanup, without fabricating a confirmed stop. No result is sealed and no resource claim is released here; those decisions remain P1-10 and later.

Schema version **7** adds append-only launch, process identity/observation, raw checkpoint and provider-event tables. SQL guards enforce issue ordering, monotone durable checkpoints, byte-range coverage and concluded supervision history. Earlier migrations remain unchanged.

## Limits and next gate

This is a macOS/Unix fixture process manager, not installed Claude/Codex compatibility or subscription certification. `ps` start times have one-second resolution and are observation metadata; no signal is authorized by that timestamp alone. Process groups and sampled descendant discovery are not containment for hostile processes or invisible detached descendants. Known escaped processes are retained as unconfirmed instead of risking an unrelated PID. An unknown pipe holder can keep a bounded reader thread blocked until it exits; the control loop still returns unconfirmed and retains claims. Best-effort cleanup under OS failure cannot guarantee death and never claims it did. No B6–B8 CPU/RSS/p99 benchmark certification is claimed; flood tests verify functional bounds. Other config/instruction/permission digests remain explicit caller-supplied references, not live-provider assurance.
