## Implementation and storage

The domain contains explicit revisioned nodes, identified edges and artifact/execution graph kinds. Validation rejects missing or wrong-revision endpoints, duplicate nodes/edges, self-edges and cycles. Stable Kahn ordering includes isolated nodes; iterative DFS returns a closed, deterministic cycle path. Limits are 512 nodes and 4,096 edges per graph, with the existing bounded strict JSON parser for canonical imports.

Migration **4** appends immutable `execution_plans`, `graph_nodes`, `graph_edges`, `dependency_observations` and `dependency_attempt_inputs` tables to the existing database. Endpoint foreign keys and uniqueness/check constraints reinforce writer validation. Update/delete triggers preserve plan, observation and input history. Old migrations remain unchanged.

Canonical plan bytes include both graphs, step/source revisions, selected outputs, upstream artifact decisions, permission and validation digests, and required output inventory. They are the existing P1-04 review-document body, so graph edits require a new revision and human approval. Plans must bind applicable approved PRD/ADR revisions and all artifact graph nodes. Hash checks and strict imports protect reads; the existing writer supplies transactions, event causation, receipts, epochs and idempotency.

## Predicate semantics

Dependency schema **1** is a closed set with no expression/script language or PR-open predicate:

| Predicate | Required exact binding |
| --- | --- |
| Artifact approved | Current human decision, revision, canonical and review-bundle hashes |
| Output available | Selected output ID, producer revision, output digest and source vector |
| Code verified | Independent receipt, source, reviewed validation-plan digest and nonempty test inventory |
| PR merged | Authoritative merge observation and exact source |
| Build available | Build artifact digest and exact source |
| Deployed healthy | Artifact digest, source, environment and current independent receipt |
| Contract compatible | Reviewed compatibility-bundle digest and both repository/source sides |
| Validation passed | Independent checks, validation-plan digest, inventory and source/environment selectors |

The one canonical evaluator returns SATISFIED, UNSATISFIED or UNKNOWN, with reasons, evidence/version references, required and observed source identities, artifact bindings and effective expiry. Missing/failed lookups, unsupported schemas, uncertain clock scope and stale evidence block. Wrong selectors, explicit failure/invalidation and PR-open observations never satisfy. Both injected wall and monotonic time constrain freshness; a clock-epoch change requires reobservation.

Event, reconciliation, recovery and prelaunch entry points use the same evaluator and snapshot semantics. Artifact constraints and applicable approvals are plan prerequisites; execution edges AND-combine over the dependent and its prerequisite ancestry. Invalidation conservatively blocks descendants while independent branches remain eligible.

## Source materialization and invalidation

Materialization resolves a declarative source vector, without Git or filesystem effects. Sources name exact repository identities and full commit IDs or base-commit/snapshot digests. Root bases are explicitly reviewed; predecessor outputs require exact OUTPUT_AVAILABLE selections. Duplicate/conflicting repository sources and source vectors inconsistent with dependency evidence are rejected. No branch-tip or “latest” fallback exists.

Observed materialization bases and environment must equal the reviewed vector. Reservation freezes that vector durably. A prelaunch revalidation API checks fresh local observations and returns a blocked verdict successfully, allowing its stop intent to commit rather than being rolled back as a command error. The legacy P1-04 reservation API refuses typed plans, preventing a dependency/source bypass.

Observation changes and approval/plan edits reconcile dependencies transactionally through P1-04's existing stop-intent boundary. Periodic/recovery/prelaunch reconciliation also detects expiry. Stop intent survives reapproval and restart; sealed result bytes and historical plans/observations remain unchanged. No attempt is restarted or replaced.
