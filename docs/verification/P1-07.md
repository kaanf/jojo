## Implementation and transaction boundaries

Migration **6** adds immutable repository registrations, attempt-bound lifecycle records and immutable candidate references. Repository IDs derive from canonical Git common-directory path plus device/inode; linked worktrees and symlink aliases share one scheduler gate. Owned-root filesystem identity, epoch, base, branch, predecessor and ownership marker are frozen. SQL enforces identity/history retention and forward lifecycle transitions.

`request_worktree` persists WAITING and then acquires a complete exclusive repository administration claim before CREATING. Waiters block new execution admissions for that repository; existing shared holders drain and independent repositories remain available. A reservation cannot upgrade itself from shared execution into administration. Git/filesystem effects run outside SQLite transactions while the engine retains its singleton. Successful inspection produces a seal consumed by the writer; READY and administration-claim release commit together. Failures retain CREATING/BLOCKED records, claims and partial files. Repeated requests return the original lifecycle; partial creates are never replayed.

`schedule_owned_worktrees` matches pre-provisioned attempt identities to canonical repositories and atomically reserves scheduler resources plus private worktree/output writers. Its inspected binding must match the frozen dependency commit/snapshot. Reservations, including the retained P1-06 reservation-only API, are not filesystem safety evidence. No dispatcher is introduced.

Candidate packets freeze HEAD, staged and unstaged binary patches, untracked bytes, executable bits and untracked file permissions/symlink targets. Capture rejects concurrent differences and live/uncertain private-writer claims. Packets are synced, digest-checked, durably referenced and reopenable. Continuation requires that exact registered predecessor candidate and creates a new attempt directory/branch, applies changes there and verifies materialization equivalence. Originals remain untouched. Approval/session/recovery orchestration belongs to later milestones.

## Security and recovery

Only `/usr/bin/git` is launched, with argv, cleared environment, disabled hooks/fsmonitor, denied transport protocols and a closed local command set. Executable filters/included repository configuration are refused. No shell, provider, fetch, push, remote creation, reset, clean, remove, force or prune operation is generated. Traversal and protected `agentic-factory` / `research/upstream` paths are refused before and after canonicalization. Root identity, markers, reciprocal private gitdir, common-directory identity and branch bindings are checked; symlink parents/output substitutions and cross-attempt bindings fail closed.

Startup remains paused. Old-epoch operations and stale seals are rejected; incomplete administration claims quarantine through the existing boot logic. Passive inspection reports retained state without adopting, releasing or replaying anything. Dirty work is never automatically deleted or reused. This milestone does not implement full recovery resolution.
