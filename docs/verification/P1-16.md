### The single acceptance rule

After every fault the helper is crashed and reopened, then `verdict()` must classify the attempt as exactly one of:

- **Nothing**: never reserved; no claim, launch or recovery subject.
- **Hold(stage)**: no result; an explicit recovery subject with choices; every claim `QUARANTINED`.
- **Sealed(outcome)**: one immutable result; all referenced evidence verifies; no claims; a second settlement is refused. A `Succeeded` result has a candidate, no stop cause and needs no decision.

In every case reopening leaves admission closed, dispatches no attempt effect and launches no new process.

## Known limitations

- Disk failures are injected (spool limits, read-only evidence directories, writer fail points); no physical volume is filled.
- Sleep/wake and reboot are simulated (clock jumps, a new clock epoch, scripted identity results).
- Backup/restore is a cold copy of a stopped helper's data root; Phase 1 has no online backup command.
- The database file mode follows the umask; its privacy rests on the 0700 data root that `prepare_data_root` enforces.
- Same-user hostile-code isolation is **explicitly unsupported**. The channel test proves provider output cannot act as a control command, not that hostile code is contained.
