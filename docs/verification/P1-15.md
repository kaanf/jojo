## Implementation

No production Rust, Swift or protocol code changed. The gate enforces a changed-file allowlist.

- **Fake developers** (`crates/jojo-storage/src/bin/jojo-process-fixture.rs`, test-only): `claude-develop <ops>` and `codex-develop <ops>` emit a Claude `stream-json` or Codex `exec --json` session start (RUNNING), wait for the test's `release` file barrier, edit the owned worktree, then report provider-shaped success.
- **`crates/jojo-storage/tests/t15_scenario.rs`**: one scenario fixture over two independent temporary repositories (distinct content and bases) and one owned worktree root. Human decisions go through the helper's production `Service` (the SwiftUI shell's protocol): `ReviewBundle`, then `HumanDecision` bound to the displayed hash. Developers run through the real P1-09 runner, or the helper's worker pool for the close scenario. Results are settled by P1-10 settlement and validated by a separately named validator fixture (`t15-validator`). Recovery goes through P1-11 and the close through the P1-12/P1-13 coordinator.
- **Overlap proof**: `run_parallel` starts every job and waits until each reports `SessionIdentified`. Only then does it run the in-flight assertions and create the barrier. Afterwards it asserts from the runner-reported event order that every job reached RUNNING before any job's terminal or exit event. If an in-flight assertion fails, it still releases the developers so failures do not wait for the fixture watchdog.
