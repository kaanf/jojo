## Implementation

No Rust source changed: the P1-09 runner, P1-10 settlement, P1-11 recovery, P1-12 coordinator and P1-13 helper are used as they are. The gate fails if any `crates/` or `.cargo/` file changes.

- **`JojoCore` (Foundation only).** Strict JSON (integers only, duplicate keys/floats/NUL/unpaired surrogates/excess depth rejected), eight-field envelopes, 65,536-byte frames, fragmented-frame splitter. `ProcessHelperTransport` launches exactly `jojo-helper --serve` with an explicit environment (HOME only) over private pipes. It reports exit only after both stdout EOF and process exit, so a ShutdownReady frame is always processed before the exit. It has no signal, interrupt or terminate method. `HelperClient` does the handshake, session/epoch checks and request correlation. It tracks unanswered mutating commands and treats malformed output, a protocol-error frame or an epoch change as a lost channel (unknown state, not stopped). Client command IDs are random low-half values because durable receipts span sessions.
- **`QuitCoordinator`.** The one state machine for every quit path. Pending commands are reconciled by `Receipt` lookup under the original identity, never resent. Then `PrepareClose` runs: `NO_ACTIVE` goes to finalizing with no confirmation; `CONFIRM_REQUIRED` leads to `CloseStatus`, which supplies the ticket and the warning dialog. **Cancel** sends only `CancelClose(ticket)` and replies NO to AppKit at once. **Confirm Quit** sends `ConfirmClose(ticket)` once, and stopping progress then comes from `CloseStatus` polling. Termination is approved only for a ShutdownReady that matches the session, epoch and ticket, has a nonzero shutdown and event, `outcome=Ready`, `process_stop_confirmed`, `persistence_sealed` and no failures, **and** is followed by an observed helper exit of 0. ShutdownFailure, invalid proof, Ready without an exit (10 s bound), an exit without Ready, a nonzero exit or channel loss all produce a visible sticky failure and a NO reply. An active count that drops to zero is displayed but never treated as confirmation. Elapsed time never confirms anything or makes a close clean.
- **`JojoApp`.** SwiftUI views hosted in AppKit-owned windows. `applicationShouldTerminate` defers with `terminateLater` and replies later. Nothing starts in `applicationWillTerminate`. Sudden and automatic termination are disabled. Cmd-Q (SwiftUI `CommandGroup(replacing: .appTermination)`), the `kAEQuitApplication` Apple event (Dock Quit/logout) and closing the primary window all go through `AppDelegate.requestQuit`. An auxiliary Inspector window closes without quitting, and minimizing is not closure. Views cover the run list with blocked state and Cancel Task, the exact review bundle with Approve/Reject/Revoke, recovery rows with evidence locations and the four reviewed choices (display only), the quit dialog, stopping progress and the persistent failure banner. The GUI never touches SQLite.
- **Emergency paths.** A GUI crash closes the helper's stdin, and the helper runs its existing P1-12/P1-13 EOF emergency stop. When a verified close is impossible (lost channel, protocol mismatch, or a shutdown failure while the helper is alive), the only way out besides Stay is an explicit **Disconnect and Quit**. It produces that same EOF path and is recorded as `emergency-disconnect-unclean`.

Two runtime findings shaped the design; unit tests could not have exposed either:

1. **Re-entering `NSApp.terminate` while a `terminateLater` reply is pending makes AppKit terminate immediately without asking the delegate.** The first GUI run showed a duplicate Cmd-Q during the confirmation dialog killing the GUI. Duplicates therefore never reach AppKit: every entry point joins the running operation in `requestQuit`, and the Quit menu item and quit Apple event are replaced so they cannot bypass this.
2. **Main-queue blocks cannot run inside a deferred-termination run loop that was started from another main-queue block.** Helper frames and terminate scheduling therefore use `CFRunLoopPerformBlock` in common modes, and timers are also added in common modes.

**P1-13 contract discrepancy, recorded without changing the helper.** STDIO_PROTOCOL says payloads are objects, but the real helper answers absent `Receipt`/`ReviewBundle`/`ShutdownReceipt` with `"payload":null` and `Events` with a JSON list. The GUI accepts null and list payloads only on `Response` frames, as `Reply.null` and `Reply.list`, and still rejects them on every other frame type.

**Boundary update (narrowing a P1-01 placeholder rule).** P1-01 banned `Process`, `@main` and `WindowGroup` in Swift as "later-task" markers. The rule now allows `Process` only in `Sources/JojoCore/HelperProcess.swift` and scenes only in the app target. It newly bans, in Swift sources **and tests**: `kill`/`killpg`/`raise`/`posix_spawn`/`system`/`exec*`, `SIGKILL/TERM/INT/HUP/QUIT/STOP`, `.terminate()`, `.interrupt()` and `.suspend()`, plus `SQLite3`/`sqlite3_*`, `URLSession`, `Network`, `FileManager` and `NSTask`. Five new negative boundary tests cover these. Remote Swift packages remain rejected. The shared runner gained only the `P1-14 → p1_15` recommendation key.

## Safety guarantees

The GUI cannot kill, signal or terminate any process; the boundary rejects such code. The Rust runner remains the only stop authority. Confirm Quit asks the helper to stop all active work; there is no background continuation after a confirmed quit or a GUI exit, because helper EOF triggers its emergency stop. Nothing is reported clean without a valid READY and an observed exit 0. Every other outcome is labelled `unverified-helper-gone`, `emergency-disconnect-unclean`, `no-helper` or `clean-with-unconfirmed-commands`. Worktrees, checkpoints, logs and durable state are never deleted by the GUI, which has no file administration. Interruption is distinct from task cancellation. Admission, ownership, shutdown and recovery invariants are unchanged.

## Limitations

- Protocol 1.0 has no Start or recovery-resolution command. Active-work GUI scenarios therefore use a test-only protocol fixture (`scripts/tests/fake_helper_p1_14.py`, which launches and signals nothing), and recovery choices are display-only. The real helper's active-close behaviour is covered by the retained T12/T13 Rust tests.
- Runtime GUI steps call the real Cmd-Q menu key equivalent, a real quit Apple event, `NSWindow.performClose` and the dialog button handlers in-process. They are not Accessibility-driven mouse clicks, and visual layout is not asserted.
- After SHUTDOWN_FAILED the helper exposes no retry or escalation command, so the choices are Stay (failure visible) or an explicit unclean Disconnect and Quit.
- Logout/shutdown via the quit Apple event is deferred like Cmd-Q; macOS may report that Jojo interrupted logout.
- The app is an unbundled SwiftPM executable: no signed `.app`, helper embedding or notarization. Review content is limited to the protocol's bounded review DTO fields.

Token efficiency: targeted reads of the contracts and helper response code; context-indexed large outputs; one fake helper reused by unit and GUI tests; focused Swift/GUI subsets during development before the full gate. Provider token counts and costs are unavailable and are not estimated; no model or provider was invoked by the code or tests.
