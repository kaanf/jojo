## Implemented architecture

A three-package Cargo workspace separates pure domain vocabulary, a configuration-only
helper executable, and a dev-only fixture library. Typed feature/plan/step/repository/
worktree/attempt identities and revision references support many independent attempts;
there is no singleton execution slot. Attempt descriptors capture injected IDs and time
without ambient clock/environment reads. Lifecycle/outcome/intent enums are vocabulary,
not an implementation of state transitions or result settlement. Configurable concurrency
and stop budgets are policy data, not a scheduler or signal engine.

The helper parses explicit configuration, reads only HOME for default macOS roots,
validates lexical absolute/non-overlapping roots and exits. Defaults are separate sibling
Application Support roots. Explicit roots work without HOME. It creates no directories,
reads no provider credentials, launches no children, listens on no socket, and cannot
execute a job. No-argument and unrecognized execution invocations fail with exit 2.

A dependency-free Swift package compiles a native SwiftUI scene protocol. It is a valid
Swift project/module boundary, **not a runnable app bundle**. Views, windows, last-window
quit behavior, AppKit termination coordination and IPC remain P1-13/P1-14. No visual UI
was developed, and no GUI behavior is represented as working.

SQLite authority, CAS/commands/events, singleton locking/epochs, actual approval validation,
DAGs/scheduling/fairness, provider adapters, worktree operations, process supervision,
shutdown/recovery and evidence settlement remain unimplemented. Test fixtures supply
clock/ID values only; full fake-provider DTOs/adapters belong to P1-08.

## Deviations and remaining risks

No approved architectural invariant was changed. The SwiftUI boundary is a Swift package
library rather than an Xcode application target; this intentionally fulfills P1-01's
project-boundary scope without implementing P1-14. There is no app lifecycle claim.

Production ID generation and system clocks are not installed; test sequences are scoped,
in-memory and not restart-safe. Root validation is lexical and cannot guarantee symlink
containment, ownership or 0700 permissions. Those guarantees must precede future disk work.
No preservation/retention engine exists yet; there is also no deletion operation.

The static guard is a regression allowlist, not an adversarial compiler/security proof.
Empty-home/environment and network denial do not isolate all host files from hostile code.
Real provider compatibility/auth/billing assurance remains U06; this phase cannot establish
it. The verifier requires preinstalled macOS tooling and `sandbox-exec`; it fails closed
when unavailable and installs nothing. Reproducible tests/locked inputs do not promise
bit-identical builds across Apple SDK/toolchain changes. No runtime migrations, scheduling,
process-stop or recovery tests from T02+ were performed or claimed.
