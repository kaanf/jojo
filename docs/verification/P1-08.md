## Implementation and authority boundaries

`jojo-domain::provider` defines schema-versioned LaunchSpec, provider/version/parser/config fingerprints, capabilities with Supported/Unsupported/Unknown, categorical readiness/auth, continuation references, permission envelopes, normalized evidence and correlated input/tool-permission DTOs. LaunchSpec freezes attempt/step/plan/worktree bindings, engine epoch, generation, source/config/instruction references, bounded prompt and its digest, role, cwd/output paths, environment names, approval references, required outputs and validation reference. Structural validation rejects unsupported schema, missing bindings/references, oversized prompt, invalid limits, relative/traversal paths, non-allowlisted environment names and network/hooks/background effects.

`jojo-test-support::provider` implements distinct FakeClaude and FakeCodex adapters over the neutral prepare contract. Both use explicit caller-supplied synthetic capability/readiness facts; no host inspection occurs. Exact fingerprint agreement, known native-subscription readiness and required capabilities precede session creation. Optional unknown/unsupported input, permission, interrupt and continuation modes fail explicitly. Changed-cwd continuation needs explicit support and a reviewed continuation reference/new attempt.

Each prepared fake session privately owns its immutable LaunchSpec, exact session/turn binding, sequence, pending request, cancellation state and script. Scripts deterministically interleave records, named wait/release barriers and failures without sleeps or shared mutable adapter state. Input matches attempt/generation/provider/session/turn/question/revision; permission replies use a separate restricted decision/deadline API and cannot manufacture product approvals. Interrupt acknowledgement makes no claim of process death. Raw references and event identities remain explicit. Protocol/correlation/raw-reference failures latch the session closed, preventing subsequent success normalization.

Provider terminal success remains evidence only. Adapters cannot emit authoritative OS process-start/exit observations and have no storage dependency, handles or resource/result/approval mutation API. A database integration test records a forged success/approval/release diagnostic and verifies durable aggregate state and claims remain unchanged and no result appears. Existing fake-provider approval-denial regressions also remain required.
