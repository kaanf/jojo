## Implementation

**Ordered classification (`jojo-domain::outcome`).** This is a pure function over durable facts. Rules apply in this order:

1. Unconcluded supervision, uncertain spawn or `STOP_UNCONFIRMED` returns `RecoveryRequired`.
2. A stop without a recorded cause returns `RecoveryRequired`.
3. Lost coverage returns `RecoveryRequired`.
4. Not-spawned launches follow their stop cause.
5. A stop committed before finalization outranks any terminal record:
   - task cancel → CANCELLED
   - revocation or invalidation → INTERRUPTED
   - shutdown → INTERRUPTED
   - supervisor protocol, deadline or descendant stop → FAILED
6. Otherwise:
   - protocol violation or duplicate terminals → `FAILED(protocol_violation)`
   - known truncation → `FAILED(output_truncated)`
   - unknown wait status → `RecoveryRequired`
   - no terminal → `FAILED(protocol_incomplete)`
   - terminal error, interrupted or unknown → FAILED
   - terminal success with a nonzero exit → `FAILED(exit_mismatch)`
   - terminal success with an unknown effect or missing candidate → `RecoveryRequired`
   - unsupported required output → FAILED
   - only otherwise → SUCCEEDED

A terminal success seen after a stop is kept as an uncertainty, as evidence.

**Stop causes.** Every existing stop path now records its first cause in the same writer transaction: attempt cancel, step CANCEL, approval/dependency invalidation, supervisor reason constants, and the new `request_shutdown_stop`. Once a result is sealed, no cause is recorded, so a later cancel cannot reorder history.

**Settlement (`jojo-storage::outcomes`).**
- `begin_attempt_settlement` requires a current-epoch launch and a SQL-proven `TREE_ABSENT`. It releases only the private `worktree:<attempt>` writer claim.
- `prepare_settlement` collects and records the candidate. It publishes each raw spool only if its length equals the durable checkpoint, then verifies every referenced blob on disk.
- `finalize_attempt_result` re-reads all facts in one transaction. It refuses evidence changed after verification and old-epoch attempts. It then either appends a recovery hold, or seals exactly one result. Sealing writes `attempt_results` and `approval_results`, sets FINISHED, seals the reservation, puts the step on HOLD (no automatic re-dispatch), and releases holder claims with `HolderSettled` only if no effect outcome is unknown.

Results never come from in-memory launch reports or provider prose.

**Evidence (`jojo-storage::evidence`).** Blobs are content-addressed and stored under the private data root. Each write goes to a unique 0600 temporary file, is fsynced and renamed to a 0400 file named by its digest, and the directory is fsynced before any reference commits. An existing blob is verified, never replaced. SQL ties log blobs to the durable checkpoint size and candidate blobs to a recorded candidate, and refuses evidence after sealing. Missing or changed referenced blobs become lost coverage and are never reconstructed. `orphans()` lists sweepable leftovers but never deletes them.

**Effect journal.** `journal_attempt_effect` records an effect as NOT_ISSUED under a unique `attempt-effect:` key. `issue_attempt_effect` moves it to ISSUED_UNKNOWN before any external call. Only a `fake-remote:` observation of the exact payload digest can confirm or reject it. A lost acknowledgement stays ISSUED_UNKNOWN. Such an effect is never dispatchable, cannot be re-issued or re-journaled, blocks success, and keeps claims after a non-success seal.

**Independent validation (`jojo-domain::validation`, `jojo-storage::validation`).**
- **Plan binding.** A canonical, strictly imported validation plan declares, per step, a non-empty write scope, baseline paths and an exact test inventory. Overlapping or nested entries are refused as ambiguous ownership. Its digest must equal the approved plan's existing `validation_digest`, so this adds no schema change to the reviewed plan.
- **Changed paths.** `inspect_candidate_changes` gets them from repository evidence. It runs `git diff --raw -z --no-renames <frozen base>` plus an untracked listing through the existing closed Git surface. It requires the current epoch, ownership checks and an absent writer, and re-captures the worktree before and after so it provably reproduces the sealed candidate digest.
- **Fail-closed entries.** Submodules, unknown statuses, unsupported modes, non-UTF-8 or non-normal paths, ignored and special files all fail closed.
- **Receipts.** The engine decides out-of-scope paths, baseline modification, zero/missing/extra/duplicate/failed tests, plan forgery, validator plan mismatch and stale approvals. The validator supplies only a typed report through a trusted host entry point, and the report is retained as a blob.
- **Acceptance.** Acceptance is a separate human, append-only assessment. It needs a SUCCEEDED invocation, the latest passing receipt and approvals that are still current at acceptance time.

**Schema version 8** adds `attempt_stop_causes`, `evidence_blobs`, `attempt_evidence`, `attempt_effects`, `effect_observations`, `attempt_results`, `attempt_recovery_holds`, `validation_plans`, `validation_receipts` and `candidate_acceptances`. Every table has update/delete triggers. Insert guards:
- A result requires `TREE_ABSENT` or `NOT_SPAWNED`.
- Success requires `TREE_ABSENT`, candidate and both log evidence rows, exit 0, no stop and no ISSUED_UNKNOWN effect.
- PASSED requires the sealed candidate.
- Acceptance requires PASSED and SUCCEEDED.

Earlier migrations are unchanged. Assertions in earlier tests that hard-code the latest schema version were moved from 7 to 8, as previous milestones did.

T10 tests cover the following:
- exit-zero/no-terminal → `protocol_incomplete`
- terminal-success/nonzero-exit fails
- lost coverage from a tampered spool stays recovery-required with claims held and no re-publication
- cancel before finalization → CANCELLED with the terminal success retained; cancel after finalization changes nothing
- shutdown and mid-run revocation → INTERRUPTED
- concurrent finalizers → one winner
- SQL refuses result/receipt mutation and premature success
- a missing or corrupt blob blocks and is never reconstructed
- blob faults before or after rename leave only orphans, then a clean retry seals
- a STOP_UNCONFIRMED process cannot finalize
- an effect whose acknowledgement was lost stays ISSUED_UNKNOWN, is never replayed (including across an unclean restart), and is resolved only by an exact fake observation
- a fake developer that edits a baseline test and out-of-scope files while reporting success fails validation and acceptance
- deletes, mode changes, rename halves, symlinks and sibling-prefix paths are caught
- zero, missing, failed, extra, forged-plan and stale-approval validations fail
- ignored files or a worktree edited after sealing fail closed with no receipt, and user files are retained
- a restart preserves the result and its evidence

## Limits and next gate

- Immutability is enforced by policy, SQL triggers and digests. It does not resist a hostile same-user process, and blob verification precedes the sealing transaction.
- Scope evidence covers repository content only. It does not cover writes outside the worktree, reads, or effects that were not journaled.
- The validator process run, and feeding accepted outputs into dependency predicates, belong to P1-15 integration.
- `APPROVAL_INVALIDATED` also covers dependency invalidation. Unrecognised supervisor stops seal as `INTERRUPTED(supervisor_stop)`.
- Recovery holds for old-epoch attempts, lost coverage, unknown effects and unconfirmed stops are recorded, not resolved. Resolving them is P1-11.
