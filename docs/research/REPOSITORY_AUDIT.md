# Open-source repository audit — Stage 1

Audit date: 2026-11-14. Scope: a single-user, local-first feature development factory with SwiftUI and a Rust core. Status: research and proposals only; nothing here constitutes approval to implement.

## Recommendation

Build a focused Rust orchestration core. Adapt Spec Kit's feature and clarification content; port a small subset of OpenSpec's artifact graph and Optio's reconciliation semantics after correcting the mismatches documented below. Run the official Claude Code and Codex binaries, Maestro and OSV-Scanner externally. Do not adopt Optio or Backstage as the application framework. Keep the native GUI independent of execution lifetime.

## Reproducibility and audit limits

All eight requested repositories were cloned with `git clone --depth 1` into the directories below; official `openai/codex` was added to verify Optio's adapter against its actual upstream protocol. These are default-branch source snapshots, not tested release recommendations. The full commit is the identity; names, tags and README claims are not substitutes. Remote URLs, commit dates and license file hashes are in [REPOSITORY_PINS.json](../../research/REPOSITORY_PINS.json). [SOURCE_FILES.json](../../research/evidence/SOURCE_FILES.json) records hashes of cited implementation and test files. Every GitHub source link in these documents embeds its full audited SHA.

No upstream source was edited, dependencies installed, builds run, agent inference invoked, API keys used or remote repositories created. Tests described below were **read, not executed**. Conclusions establish implementation evidence and design suitability, not proven operational reliability. No dependency-wide vulnerability scan, complete SBOM or exhaustive transitive-license clearance was performed. A static inspection can identify a risky code path without proving an exploitable deployed vulnerability.

## 1. Optio

**Decision: PORT selected semantics; REWRITE local execution and persistence; DISCARD hosted platform infrastructure.** MIT, [`LICENSE`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/LICENSE).

Implementation examined:

- [`packages/shared/src/reconcile/types.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/shared/src/reconcile/types.ts) defines spec/status/world/action boundaries for repository tasks, standalone workflows, PR reviews and persistent agents. [`packages/shared/src/reconcile/reconcile-repo.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/shared/src/reconcile/reconcile-repo.ts) decides one action from current observations. This is a useful reconciliation boundary rather than a generic claim of reusable orchestration.
- [`apps/api/src/services/reconcile-executor.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/api/src/services/reconcile-executor.ts) uses `updatedAt` compare-and-swap before mutations; [`apps/api/src/workers/reconcile-worker.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/api/src/workers/reconcile-worker.ts) schedules delayed retries and periodic resync. These are port candidates, with stronger transactions and integer revisions in Rust.
- [`packages/agent-adapters/src/types.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/agent-adapters/src/types.ts) offers streaming parsers and config construction, but its container/secrets interface is not our local CLI contract. Claude's parser handles final structured errors even with exit zero; Codex's parser has a protocol mismatch discussed in [OPTIO_INTERNALS.md](OPTIO_INTERNALS.md).
- [`apps/api/src/services/dependency-service.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/api/src/services/dependency-service.ts) stores task edges, enforces an ownership/workspace boundary, checks cycles and wakes dependents. It does not prohibit different repository URLs within that boundary: cross-repository task edges are already possible. It lacks deployment and artifact predicates.
- [`packages/container-runtime/src/run-protocol.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/container-runtime/src/run-protocol.ts) supports detached pod execution and offset replay. [`packages/container-runtime/src/process.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/container-runtime/src/process.ts) is a different local process implementation with weaker recovery semantics. Worktrees are generated by [`apps/api/src/services/repo-pool-service.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/api/src/services/repo-pool-service.ts), not by the agent adapter.

Runtime: TypeScript monorepo; Node `>=26.12.1 <27`, pnpm 10, Fastify, Drizzle/PostgreSQL, BullMQ/Redis, Docker/Kubernetes, Next/React web UI, `node-pty` local terminal support; see [`package.json`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/package.json), [`apps/api/package.json`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/api/package.json) and [`apps/cli/package.json`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/cli/package.json). iOS source also exists; it is not an already-built macOS SwiftUI-to-Rust bridge.

Tests inspected: [`packages/shared/src/reconcile/reconcile-repo.test.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/shared/src/reconcile/reconcile-repo.test.ts) covers read failures, intents, capacity and PR decisions; [`apps/api/src/services/reconcile-executor.test.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/api/src/services/reconcile-executor.test.ts) covers CAS failures; [`apps/api/src/services/dependency-service.test.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/apps/api/src/services/dependency-service.test.ts) explicitly expects `PR_OPENED` dependencies to count as met; [`packages/container-runtime/src/fake-protocol.test.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/container-runtime/src/fake-protocol.test.ts) exercises detached protocol/kill behavior; [`packages/container-runtime/src/process.test.ts`](https://github.com/jonwiggins/optio/blob/f5f5b86da3cfa75e240637292a299dc5c6ffc5ba/packages/container-runtime/src/process.test.ts) covers the process placement. These tests do not establish permission to forward provider credentials.

Security: permission bypass defaults, credential forwarding, destructive worktree cleanup, protocol drift and unknown-CI handling require changes. Preserve MIT notices for copied/adapted expression. Full internals and limitations: [OPTIO_INTERNALS.md](OPTIO_INTERNALS.md).

## 2. GitHub Spec Kit

**Decision: REUSE adapted feature/discovery templates; REWRITE the product's workflow and approval engine.** MIT, [`LICENSE`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/LICENSE).

[`templates/spec-template.md`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/templates/spec-template.md) provides prioritized, independently testable user stories, Given/When/Then scenarios, requirements, entities, outcomes and assumptions. [`templates/commands/clarify.md`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/templates/commands/clarify.md) defines an ambiguity taxonomy and prioritizes questions by impact and uncertainty, asking sequentially and recording clarifications. Its five-question cap is a workflow choice; it cannot mean every requirement is complete. [`templates/plan-template.md`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/templates/plan-template.md) and [`templates/tasks-template.md`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/templates/tasks-template.md) separate planning from implementation tasks.

This snapshot is **more than prompts and scripts**: [`src/specify_cli/workflows/engine.py`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/src/specify_cli/workflows/engine.py) implements execution, persisted run state, branching, fan-out/fan-in and resume. JSON checkpoints use temporary files and replacement. [`src/specify_cli/workflows/step/gate/__init__.py`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/src/specify_cli/workflows/step/gate/__init__.py) implements TTY choices, non-TTY pause and verdict-input resume; [`workflows/speckit/workflow.yml`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/workflows/speckit/workflow.yml) supplies spec and plan review gates. Those are genuine partial approval functionality, but not approvals bound to immutable PRD/ADR hashes, nor a deployment-aware cross-repository engine.

[`src/specify_cli/command_init.py`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/src/specify_cli/command_init.py) handles scaffold initialization and optional extensions. [`src/specify_cli/_project.py`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/src/specify_cli/_project.py) checks project boundaries and symlinks. Do not import its extension ecosystem just to render a few Markdown artifacts: it adds installation, command execution and compatibility surfaces.

Runtime: Python >=3.11, Typer/Click, PyYAML, Pydantic, Lark, MCP plus Bash/PowerShell/Python project scripts ([`pyproject.toml`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/pyproject.toml)). Markdown content is language independent. A line-by-line Python-to-Rust workflow port is unlikely to be cheaper than a narrow typed engine.

Tests inspected: [`tests/test_clarify_stage_gate.py`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/tests/test_clarify_stage_gate.py) checks that prompt deferral cannot swallow acceptance/NFR questions; this is a text regression test, not evidence of model discovery quality. [`tests/specify_cli/workflows/test_command_resume_state.py`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/tests/specify_cli/workflows/test_command_resume_state.py) tests symlinked ownership boundaries. [`tests/specify_cli/workflows/test_command_resume.py`](https://github.com/github/spec-kit/blob/2ee2b1e8005905db05f5717300a469b3068b908f/tests/specify_cli/workflows/test_command_resume.py) covers resume CLI behavior. Need our own semantic completeness and approval invalidation tests later.

Security/license: templates are executable instructions when handed to agents; review them as trusted input. Workflow shell steps run with user privileges; `requires` is not a capability sandbox (explicit in engine source). Retain MIT attribution for adapted templates. Do not run template installation or extension hooks during this audit.

## 3. OpenSpec

**Decision: PORT the small artifact graph contract; REUSE selected specification conventions; REWRITE acceptance and approvals.** MIT, [`LICENSE`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/LICENSE).

[`src/core/artifact-graph/graph.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/artifact-graph/graph.ts) implements Kahn topological ordering, deterministic declaration-order ties, readiness and unmet dependencies. [`src/core/artifact-graph/schema.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/artifact-graph/schema.ts) rejects duplicate IDs, missing references and cycles with a cycle path. [`schemas/spec-driven/schema.yaml`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/schemas/spec-driven/schema.yaml) wires proposal → specs/design → tasks → apply. This is an **artifact** graph, not a cross-repository execution scheduler.

[`src/core/artifact-graph/state.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/artifact-graph/state.ts) infers completion from generated file existence through output discovery. That is useful for authoring progress, insufficient for content quality, user approval or test proof. [`src/core/validation/validator.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/validation/validator.ts) separately validates specifications/deltas and scenarios. Validation does not convert existence into signed-off product intent. [`src/core/parsers/requirement-blocks.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/parsers/requirement-blocks.ts) and [`src/core/specs-apply.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/specs-apply.ts) provide delta parsing/application; do not port this whole Markdown dialect unless compatibility becomes a requirement.

This snapshot also has external spec stores, references and personal worksets: [`src/core/worksets.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/worksets.ts) and [`src/core/relationship-health.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/core/relationship-health.ts). A workset groups local working views; relationship health is explicitly read-only availability/metadata inspection. Neither is evidence of deployment-gated execution. Avoid the outdated claim that OpenSpec cannot organize work across roots at all.

Runtime: TypeScript/Node >=22.12, pnpm, YAML, Zod, Commander and filesystem globs ([`package.json`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/package.json)). The graph is a small, portable Rust target; content-existence semantics must change. Prefer one canonical feature format over running Spec Kit and OpenSpec as competing state owners.

Tests inspected: [`test/core/artifact-graph/graph.test.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/test/core/artifact-graph/graph.test.ts) covers linear/diamond ordering; [`test/core/artifact-graph/schema.test.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/test/core/artifact-graph/schema.test.ts) validates malformed graphs and cycles; [`test/core/artifact-graph/state.test.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/test/core/artifact-graph/state.test.ts) explicitly tests existence-based completion. [`test/core/validation.scenario-steps.test.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/test/core/validation.scenario-steps.test.ts) covers scenario-step validation. Test semantics can inform our Rust fixtures while preserving notices if adapted.

Security/license: constrain artifact output paths and imported schemas; model-authored Markdown is untrusted content. External CLI telemetry is opt-out in [`src/telemetry/index.ts`](https://github.com/Fission-AI/OpenSpec/blob/ea635dd255f8686dcf48626bbcbe0e3fd59b6067/src/telemetry/index.ts). MIT applies to copied schema/template text too.

**Decision: EXTERNAL TOOL for dependency vulnerability evidence; DISCARD a Rust scanner port.** Apache-2.0, [`LICENSE`](https://github.com/google/osv-scanner/blob/80fe50567a5d6e0ec408353e2ceacca1561b91be/LICENSE).

[`pkg/osvscanner/osvscanner.go`](https://github.com/google/osv-scanner/blob/80fe50567a5d6e0ec408353e2ceacca1561b91be/pkg/osvscanner/osvscanner.go) exposes `ScannerActions`, `DoScan` and distinct result/error concepts. [`pkg/osvscanner/scan.go`](https://github.com/google/osv-scanner/blob/80fe50567a5d6e0ec408353e2ceacca1561b91be/pkg/osvscanner/scan.go) configures SCALIBR extractors, annotations, network/offline behavior and vulnerability matching. [`pkg/osvscanner/osvscanner.go`](https://github.com/google/osv-scanner/blob/80fe50567a5d6e0ec408353e2ceacca1561b91be/pkg/osvscanner/osvscanner.go) notes that `ErrVulnerabilitiesFound` also covers license violations/deprecation and may exclude only-uncalled findings. ## 9. Justified alternatives and additions

**Official Codex rather than Optio's Codex parser — EXTERNAL TOOL.** Added and cloned because this comparison directly determines adapter correctness. Apache-2.0 plus [`NOTICE`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/NOTICE); SHA in pin table. [`codex-rs/exec/src/exec_events.rs`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/codex-rs/exec/src/exec_events.rs) serializes `thread.started`, `turn.completed`, `turn.failed`, `item.completed` and nested item variants. Optio's adapter primarily looks for older `message`/`function_call` shapes and misses nested assistant-message items. Its generic `error.message` envelope does catch the current `turn.failed` error shape, but its separate display parser skips that event; this is partial compatibility, not total failure. Use the official JSON protocol as authority.

[`codex-rs/app-server-protocol/src/protocol/common.rs`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/codex-rs/app-server-protocol/src/protocol/common.rs) exposes initialize/thread/turn/account RPCs. [`codex-rs/app-server-client/src/lib.rs`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/codex-rs/app-server-client/src/lib.rs) has a useful client facade, but [`codex-rs/app-server-client/Cargo.toml`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/codex-rs/app-server-client/Cargo.toml) pulls in server/core/login and many workspace crates: do not embed it merely because it is already Rust. Use the installed official CLI's app-server over stdio when richer interaction is needed; start with `codex exec --json` for bounded jobs. Tests inspected: [`codex-rs/app-server/tests/suite/v2/config_requirements_login.rs`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/codex-rs/app-server/tests/suite/v2/config_requirements_login.rs) and [`codex-rs/app-server/tests/suite/v2/turn_start.rs`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/codex-rs/app-server/tests/suite/v2/turn_start.rs) demonstrate authentication-policy and turn contracts under test. Source build uses Rust 1.99.1 at [`codex-rs/rust-toolchain.toml`](https://github.com/openai/codex/blob/7924f95421a326bb66426a3ce232b72550948470/codex-rs/rust-toolchain.toml); that does not dictate our engine's compiler version.

**Official Figma MCP — EXTERNAL TOOL, documentation-only assessment.** Prefer the vendor integration to maintaining a PAT bridge for design context. [Desktop setup](https://developers.figma.com/docs/figma-mcp-server/local-server-installation/) documents local access and seat/plan requirements; [server overview](https://developers.figma.com/docs/figma-mcp-server/) documents design context. This service was not source-audited or invoked. Existing entitlement is unknown; do not assume free access. Export import remains the prototype fallback.

**Git/gh and XCTest — EXTERNAL TOOL, existing platform capabilities rather than newly audited repositories.** Git worktrees and machine-readable gh queries avoid porting git/SCM implementation. XCTest/XCUITest is the platform path for the factory's macOS UI. Their adapters still need contract tests and version probes; they are recommendations, not newly established source-level reusability claims.
